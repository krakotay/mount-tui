# mount-tui

[English version](README.md)

`mount-tui` — интерактивный терминальный интерфейс для Linux, позволяющий
просматривать, монтировать и размонтировать локальные блочные устройства,
ресурсы SMB/CIFS и удалённые каталоги по SSH.

## Возможности

- Показывает диски, разделы, точки монтирования, типы файловых систем, размеры
  и метаданные устройств.
- Показывает, принадлежит ли примонтированная директория запустившему программу
  обычному пользователю.
- Определяет ФС непримонтированных устройств по метаданным udev, не сканируя
  само устройство и не блокируя интерфейс при ошибках диска.
- Монтирует локальные ФС с редактируемыми точкой подключения и параметрами.
- По умолчанию использует совместимые с файловыми менеджерами точки
  `/media/<пользователь>/<метка-или-устройство>`.
- Предлагает явный выбор драйвера NTFS: совместимый `ntfs-3g` (по умолчанию)
  или драйвер ядра `ntfs3`.
- Подключает и переподключает SMB/CIFS через встроенную форму учётных данных.
- Читает конкретные хосты из `~/.ssh/config` запустившего пользователя и
  монтирует удалённые каталоги через SSHFS; хост можно ввести и вручную.
- Показывает готовую строку `/etc/fstab`, экспортирует её в новый файл или
  добавляет в `/etc/fstab` с проверкой дубликатов.
- SSHFS-подключение можно сделать постоянным прямо в форме SSH.
- Читает `/etc/fstab` в отдельное, выключенное по умолчанию представление с
  проверяемым редактированием строки и подтверждением удаления.
- Передаёт пароль SMB через временный файл с правами `0600`, не показывая его
  в аргументах процесса.
- Предоставляет доступ обычному пользователю через подходящие параметры UID/GID
  либо смену владельца только корня Unix-совместимой файловой системы. Действие
  отключается, если владелец уже выбран правильно.
- Поддерживает фильтр, стандартное выделение и копирование текста мышью в
  терминале, показ pseudo FS и подробной информации.

## Требования

- Linux
- Терминал с поддержкой UTF-8 и цветов
- Права root для монтирования, размонтирования и смены владельца
- Rust 1.85 или новее для сборки из исходного кода (edition 2024)

Необязательные системные помощники:

- `ntfs-3g` для наиболее совместимого режима NTFS, выбранного по умолчанию
- `cifs-utils` (`mount.cifs`) для ресурсов SMB/CIFS
- `sshfs` для удалённых каталогов SSH

Debian/Ubuntu:

```bash
sudo apt install ntfs-3g cifs-utils sshfs
```

Fedora:

```bash
sudo dnf install ntfs-3g cifs-utils fuse-sshfs
```

Arch Linux:

```bash
sudo pacman -S ntfs-3g cifs-utils sshfs
```

## Сборка и запуск

```bash
cargo build --release
sudo ./target/release/mount-tui
```

С помощью [`just`](https://github.com/casey/just) нужный вариант можно собрать
и установить одной командой:

```bash
just install       # release-бинарник в /usr/local/bin
just install-deb   # сборка и установка DEB-пакета
just install-rpm   # сборка и установка RPM-пакета
```

Префикс установки бинарника меняется через `PREFIX`, например
`PREFIX=/usr just install`. Если упаковочные инструменты ещё не установлены,
при первом запуске они будут установлены через Cargo.

Программу можно запустить без root. При запросе привилегированной операции
нажмите `R` в диалоге, чтобы перезапустить её через `sudo`. Запуск через `sudo`
от обычного пользователя сохраняет `SUDO_UID` и `SUDO_GID`, поэтому доступ
выдаётся этому пользователю, а не root.

## Управление

| Клавиша | Действие |
| --- | --- |
| `↑` / `↓`, `PageUp` / `PageDown`, `Home` / `End` | Навигация по устройствам |
| `f` | Фильтр списка устройств |
| `r` | Обновить список подключений и устройств |
| `m` | Смонтировать выбранное локальное устройство |
| `n` | Подключить новый ресурс SMB/CIFS |
| `h` | Выбрать SSH-хост из `~/.ssh/config` или ввести его вручную |
| `u` | Размонтировать выбранную точку |
| `a` | Дать доступ обычному пользователю, запустившему программу |
| `x` | Показать/экспортировать строку fstab или добавить её в `/etc/fstab` |
| `b` | Показать или скрыть `/etc/fstab` (по умолчанию скрыт) |
| `e` / `Delete` | Изменить или удалить выбранную запись fstab |
| `i` | Показать или скрыть подробную информацию |
| `d`, `t`, `s`, `p` | Переключить диски, разделы, SMB или pseudo FS |
| `q` | Выход |

В формах работают `↑` / `↓`, `Tab` / `Shift+Tab`, `Home` / `End` и `Ctrl+U`
для очистки активного поля. В форме локального монтирования драйверы NTFS
показаны явным переключателем `[x]` / `[ ]`; выбор меняется клавишами `Space`,
`←` или `→`.
Текстовые поля показывают курсор и поддерживают редактирование в любом месте
через `←` / `→`, `Home` / `End`, `Backspace` и `Delete`. Если локальное
монтирование в режиме чтения-записи завершилось ошибкой, программа предложит
повторить попытку с теми же параметрами в режиме только для чтения.

## SMB/CIFS

Введите ресурс как `//server/share`; также принимается `smb://server/share`.
Пустое имя пользователя включает гостевой доступ. Обязательные и некорректные
значения подсвечиваются до запуска команды монтирования.

По умолчанию SMB монтируется с UID/GID запустившего пользователя,
`file_mode=0664` и `dir_mode=0775`. Действие выдачи доступа переподключает
существующий SMB-ресурс через встроенную форму. Серверные ACL по-прежнему имеют
приоритет над клиентскими параметрами.

Пароли авторизованных SMB-ресурсов никогда не попадают в экспортируемый текст
fstab. Для автоматического подключения добавьте `credentials=/путь` к файлу,
доступному только root. Для гостевых ресурсов файл учётных данных не нужен.

## SSHFS

Клавиша `h` открывает список конкретных (без шаблонов) алиасов `Host` из
`~/.ssh/config` запустившего пользователя и пункт ручного ввода. В форме можно
указать удалённый путь, локальную точку, необязательный пароль/парольную фразу
ключа, параметры SSHFS и включить добавление в `/etc/fstab`. Секрет скрыт и
передаётся `sshfs` только через stdin, а не в аргументах процесса. Пустое поле
принудительно включает неинтерактивную авторизацию по ключу или через агент,
поэтому запрос OpenSSH больше не может перехватить терминал TUI.

Настройки `User`, `HostName`, `Port` и `IdentityFile`
подхватываются автоматически, а сам конфиг передаётся SSH, поэтому продолжают
работать настройки вроде `ProxyJump`. Постоянное подключение недоступно при
парольной авторизации или без пригодного закрытого ключа. При включении опции
программа проверяет, что ключ не требует парольной фразы и сервер принимает
именно этот ключ; отсутствующий или неверный ключ оставляет опцию выключенной.
В постоянную запись также добавляются `allow_other`, `default_permissions` и
UID/GID исходного пользователя, поскольку при загрузке fstab обрабатывает root.

При запуске mount-tui через `sudo` сам SSHFS запускается от имени исходного
пользователя рабочего стола, а точка монтирования заранее передаётся ему. FUSE
поэтому записывает правильный `user_id`, и каталог сразу доступен пользователю
без повторной передачи внутренних опций FUSE.

## Экспорт и постоянные подключения

Клавиша `x` показывает точную строку fstab для выбранной файловой системы.
`E` записывает её в новый файл с правами `0600`, не перезаписывая существующий.
`P` добавляет строку в `/etc/fstab`, предварительно проверив пару источник/точка
на дубликат. Для локальных устройств по возможности используется `UUID=`, для
сетевых — `_netdev`. Отсутствующая точка монтирования создаётся, но `mount -a`
автоматически не запускается.

Клавиша `b` добавляет записи `/etc/fstab` в основной список; по умолчанию они
скрыты. Для выбранной записи `e` открывает полную исходную строку, а `Delete`
удаляет её после подтверждения. Изменения проверяются и записываются атомарно,
не затрагивая комментарии и соседние строки. Перед первым изменением или
удалением создаётся `/etc/fstab.mount-tui.bak`, если такого файла ещё нет.

## Драйверы NTFS

Для тома NTFS по умолчанию выбирается `ntfs-3g` ради совместимости. Чтобы
использовать новый драйвер ядра, выберите `ntfs3` в форме монтирования.
Если обычное монтирование `ntfs3` в режиме RW завершится ошибкой, программа
предложит выбор между RO и явно помеченным как `DANGER` (не рекомендуется)
повтором RW с опцией `force`. После ошибки RW+force будет предложен RO, а после
ошибки обычного RO — последний, также помеченный `DANGER`, вариант RO+force.
`ntfs-3g` работает через FUSE и устанавливается отдельно; при его выборе
программа вызывает соответствующий системный mount-helper.
